## Cross-domain policy consistency: still a real editorial choice

Previous [Nov 5 review](ADJACENT_FULL_SCOPE_REVIEW_20261105.md) removed **BWCache** and **Rolling Forcing** as video-only algorithms but retained selected visual/World Model papers. “Not text LLM” cannot by itself explain that difference. An objective rule for exceptional adjacent entries is **an inspectable, reusable inference execution mechanism** with measured system cost and an explicit *model/quality change* boundary:

1. **Pure model/training contribution:** useful in Frontiers as a workload driver, not automatically a canonical systems optimization.
2. **Running inference algorithm with real system cost:** eligible for adjacent if a specific dataflow, memory, device or scheduling bottleneck is exposed (e.g., db-SP); never imply the same checkpoint/hardware gain.
3. **Real serving stack or deployable runtime adaptation:** prioritize when code, version and quality are inspectable. If two works differ only in modality with comparable evidence, judge by G2/G5 novelty, *not* by their titles.

The existing two removals should be revisited under this symmetric test before further pruning. **No bulk deletion or re-admission made in this pass**; inconsistent editorial rules are a HOLD, not something to conceal by changing counts.

## Engineering reading / experimental priorities

**High relevance to runtime and kernel optimization:**
- **CODA** → whether RMSNorm/Residual/MLP producer–consumer reparameterization eliminates HBM materialization on actual NPU; preserve numerical oracle and account for auxiliary reductions, do not extrapolate H100 large-M results to Ascend Small-M.
- **Formulaic** → strong example of exposing negative full-system results, respecting reference-output equivalence, separating one-chip serving from simulated co-design; avoid treating +7.70% client throughput as cluster Goodput.
- **ReadKV** → design a **full cache-creation→storage→Decode** benchmark. Compare BF16 Dense *and* best fused quantized implementation under matched quality; if codec loses to Dense without capacity pressure, ask whether increased batch capacity pays for it.
- **TensorHub** → model-version consistency across multi-rank hot swaps; only worth an NPU test if the actual workload updates model weights frequently. Not relevant to ordinary static-weight vLLM requests.
- **TokenSim** → use for experiment planning **only after re-calibration** against pinned runtime and network; compare simulator errors on TTFT/TPOT/P95 plus cache misses/preemptions.

**Low immediate text-LLM transfer:** WorldPlay, NCM, DeepInfer-Mac, Bless, db-SP and OrbitWeaver have distinct value but demand a genuinely matching workload or specialized hardware before an Ascend reproduction. No invented speedups or compatibility claims.

## 3. Verified, bounded conclusions

1. **Finding F1 — two-layer scheduling is explicit in FastDeploy.** An external Go Router decides engine/pair placement; `resource_manager_v1.py` decides per-engine token/block and preemption; `CacheTransferManager` carries separate data movement. These cannot be collapsed into the phrase "its scheduler" or compared directly with an engine-only algorithm.
2. **Finding F2 — there is a real P/D residency/control protocol to study.** Both FastDeploy and SGLang expose Decode-side reservation/transfer components. vLLM V1 exposes a connector API. Their handoff correctness/latency contracts are not equivalent simply because they all implement P/D.
3. **Finding F3 — prefix cache spans two namespaces and two decisions.** Cluster/router prefix-affinity estimates versus engine-local physical KV ownership; cache-aware routing may fail to save end-to-end time if routing latency, remote-cache transfer and skew dominate.
4. **Finding F4 — native hardware paths must be read, not inferred.** Code/doc support for CUDA, NVIDIA GPUs, Kunlunxin XPU and CANN/Ascend are independent claims. A design comparison may transfer; a measured speedup does not.

**Not proven:** FastDeploy or Baidu beats vLLM, SGLang or other engines; a unique novel scheduling algorithm; a production-validated superiority of its native kernel path; Looped Transformer priority; a reproducible Evolve performance advantage under controlled multi-task budgets.

## 4. Best future experimental gate — documented, **not executed now**

For any actual three-way study, first choose one **identical target model/checkpoint, tokenizer, precision, attention backend, request length/concurrency distribution, arrival process, Prefix Cache configuration, GPU platform and system version** and confirm feature parity. Isolate **router overhead / engine scheduler decisions / cache bytes / P→D transfer / first-token barrier / end-to-end TTFT, TPOT and goodput**, then separately evaluate correctness and tail failures. Otherwise report only qualitative source comparison.

For the frozen Ascend environment, select **one** native vLLM-Ascend path first and independently examine plugin hooks, CANN support and actual KV cache event traces. Cross-platform FastDeploy findings should inform *which question to ask*, not provide an experimental baseline. This study's most promising **low-effort next check** is that two-layer prefix/cache-aware routing can improve cache locality yet worsen fairness or tail latency when transfer/queue costs dominate. The current evidence is **insufficient to declare a new bottleneck**.

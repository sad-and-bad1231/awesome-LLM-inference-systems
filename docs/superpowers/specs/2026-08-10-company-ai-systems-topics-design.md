# 国内公司 AI 系统专题设计

## 目标

沿用现有 DeepSeek 专题机制，在工业材料中增加 Kimi / Moonshot AI、MiniMax、GLM / 智谱 AI、阶跃星辰和字节跳动五个独立专题。专题只提供紧凑导航，记录仍保留在 JSONL 事实层，并继续参与原七主题主表、探索与归档选择。

## 数据与核对边界

- 候选以用户提供的截图为主，不做开放式大范围搜索。
- 仅写入能够由公司官方仓库、官方模型/技术页面、正式论文页或正式会议页面确认的材料。
- 排除明显第三方、归属不明、只含动态 star 数或无法确认标题/来源的条目。
- 新记录使用显式 `presentation.topic` 与 `presentation.topic_group`；不依赖摘要关键词推断公司专题。
- 原始摘要与现有未提交记录不删除、不覆盖。

## 实现

将 DeepSeek 专题的硬编码标题、说明和统一分组改为小型专题配置表。每个专题配置包含：稳定 key、展示标题、简短说明、分组及固定顺序。共享 selector 继续按 `project_key` 去重并优先非 release 锚点；共享 renderer 根据专题配置生成表格。

专题按以下顺序输出：DeepSeek、Kimi、MiniMax、GLM、阶跃星辰、字节跳动。内部 `industrial-llm-inference-systems.md` 与公开 `industry/README.md` 使用同一个批量渲染入口，因此重复生成结果一致。

分组根据各公司材料保持紧凑，原则上覆盖模型/架构、推理与系统、训练与数据、多模态/Agent、工具与生态；没有记录的分组不显示。DeepSeek 既有分组和输出语义保持兼容。

## 验收

- 六个专题均由显式标签选择，第三方或未标记记录不会混入。
- 同项目多个 release 只显示一次，专题及分组顺序固定。
- 两份工业视图包含相同专题集合，每个标题只出现一次。
- 展示摘要仍使用共享压缩逻辑，不出现 release HTML。
- 全量测试、`render`、`publish`、`validate` 通过，重复生成无漂移。
